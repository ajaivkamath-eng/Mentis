# Design System Spec — Mentis DS v2 “Deep Court”

Version **2.0.0** · Codename **Deep Court** · Source of truth **`packages/core/src/tokens.ts`**
Platforms: **web** (React 19 + Tailwind v4 + Framer Motion) · **native** (Expo 54 + Reanimated 4 + NativeWind)

> *Deep court* is the colour of a table-tennis hall under match lighting: deep navy structure, kingfisher-teal
> action, medal-gold achievement. One system, two platforms, zero duplicated values.

---

## 1. Governance — how the system stays honest

```
packages/core/src/tokens.ts            ← the only place a value is authored
        │
        ├── apps/web/src/app.css       → CSS custom properties (:root / .dark) + Tailwind @theme map
        └── apps/mobile
              ├── lib/theme.tsx        → typed access for StyleSheet (r, s, d, type, family)
              ├── tokens.json          → generated by scripts/gen-tokens.mjs (--check in CI)
              └── tailwind.tokens.js   → feeds tailwind.config.js so className → var(--token)
```

Change a token here and both platforms follow — or CI fails:

1. `tests/design_tokens.test.ts` asserts core ↔ web `:root`/`.dark`/`@theme` ↔ native `:root`/`.dark` ↔
   generated JSON, plus radii, type scale, spacing rhythm and elevation shapes.
2. `npm run tokens:check` in the mobile app re-generates `tokens.json` in memory and diffs it.
3. The CI job matrix runs the domain tests, the web build/tests, the mobile typecheck and the token check.

**Rules**

- Never author a hex, radius, duration or font size in a component. If a value is missing, add a token.
- Raw palette ramps exist to build semantic tokens; components only reference semantic tokens
  (`text-ink-muted`, `var(--surface-raised)`, `colors.brandSoft`) so a theme flip stays a one-file change.
- Prefer derivation over duplication: `withAlpha()`, `color-mix(in oklab, …)`, `toneForStatus()`.
- Every token must survive both themes and both platforms. If it cannot, it is not a token.

**Dark is the product default** (coaches mark registers in halls, at night, on phones). Light is a first-class
citizen, not an afterthought: both themes are authored in `darkTheme` and `lightTheme` and both are asserted.

carry an accessible name).

| Role | Family | Notes |
| --- | --- | --- |

| `sm` | 0.8125rem | 13 | 1.25rem | 0.005em |
| `base` | 0.9375rem | 15 | 1.5rem | 0 |
| `lg` | 1.0625rem | 17 | 1.65rem | -0.005em |
| `xl` | 1.25rem | 20 | 1.8rem | -0.01em |
| `2xl` | 1.5rem | 24 | 2rem | -0.015em |
| `3xl` | 1.875rem | 30 | 2.3rem | -0.02em |
| `4xl` | clamp(2rem, 1.6rem + 1.6vw, 2.5rem) | 40 | 1.1 | -0.025em |
| `display` | clamp(2.25rem, 1.5rem + 2.6vw, 3.25rem) | 52 | 1.05 | -0.03em |

**Rules**

- One display idea per screen (page title **or** hero KPI), everything else is body.
- Tracking tightens as size grows: `0` at body, `-0.02em` at heading, `-0.03em` at display.
- Uppercase is reserved for eyebrows/overlines with `0.09em` tracking.
- Web scale is fluid (`clamp()` from 360 → 1440 px); native uses the desktop value of each step so the two
  platforms read identically on a phone.
- Line heights are part of the token — never set `leading-*` by hand.

| `sm` | 9 px | `rounded-sm` |

### 4.3 Elevation

| Level | Web | Native (iOS / Android) | Use |
| --- | --- | --- | --- |
| `e1` | `0 1px 2px rgba(2,6,23,.06), 0 1px 3px rgba(2,6,23,.08)` | opacity .08 / elevation 1 | Resting cards, inputs |
| `e2` | `0 4px 10px -2px rgba(2,6,23,.10), 0 2px 6px -2px rgba(2,6,23,.08)` | .12 / 3 | Hover lift, sticky headers |
| `e3` | `0 14px 30px -10px rgba(2,6,23,.28), 0 6px 14px -6px rgba(2,6,23,.16)` | .22 / 8 | Popovers, dropdowns, mobile sheets |
| `e4` | `0 32px 64px -18px rgba(2,6,23,.45), 0 12px 28px -12px rgba(2,6,23,.28)` | .34 / 16 | Modals, command palette |
| `glowBrand` / `glowAccent` | `0 10px 30px -10px rgba(20,184,166,.55)` / gold | same hue at .45 / elevation 6 | Primary button hover, hero CTAs |

On native the same preset renders as shadow props on iOS and `elevation` on Android; dark mode multiplies iOS
shadow opacity by 1.6 (`shadow()` in `lib/theme.tsx`) so depth stays visible on deep navy.

Panels also carry `sheen` (a 1 px top hairline) instead of a heavier shadow — light comes from above, once.

### 4.4 Z-index ladder

`base 0 · raised 10 · sticky 20 · nav 30 · overlay 40 · modal 50 · popover 60 · toast 70 · command 80`

If a new layer needs a number, it belongs in this ladder, not in a component's `style`.

## 5. Motion

Motion is meaning: it explains where something came from, what it belongs to, and that the system heard you.

### 5.1 Primitives

| Duration | Value | Use |
| --- | --- | --- |
| `instant` | 90 ms | State confirmation on the element you just touched |
| `fast` | 140 ms | Hover / press feedback, colour + scale |
| `base` | 220 ms | Default UI transition (menus, popovers, tabs) |
| `smooth` | 340 ms | Surfaces entering — cards, rows settling |
| `deliberate` | 520 ms | Sheets, page transitions, hero moments |
| `ambient` | 2400 ms | Ambient loops (aurora drift, shimmer) |

| Easing | Cubic-bezier | Use |
| --- | --- | --- |
| `standard` | `cubic-bezier(0.2, 0.8, 0.2, 1)` | General purpose — quick out, soft in |
| `decelerate` | `cubic-bezier(0.16, 1, 0.3, 1)` | Entering the screen (expo-out) |
| `accelerate` | `cubic-bezier(0.4, 0, 1, 1)` | Leaving the screen — hold, then leave |
| `emphasized` | `cubic-bezier(0.22, 1, 0.36, 1)` | Sheets and modals (overshoot-free) |
| `inOut` | `cubic-bezier(0.65, 0, 0.35, 1)` | Symmetric, for looping/ambient movement |

| Spring | Stiffness / damping / mass | Use |
| --- | --- | --- |
| `swift` | 420 / 34 / 0.8 | Buttons, chips, toggles — tight and immediate |
| `gentle` | 240 / 26 / 1 | Cards, sheets, list reorder |
| `bouncy` | 520 / 16 / 0.9 | Playful moments — success ticks, badges |
| `sheet` | 300 / 30 / 1.1 | Long-travel swipes and drawers |

### 5.2 Presets (one name, two implementations)

| Preset | Value | Web | Native |
| --- | --- | --- | --- |
| `press` | 0.97 scale, 90 ms spring `swift` | `whileTap` on buttons/rows/cards | `usePressScale()` + `Haptics.selection()` |
| `hoverLift` | −2 px + shadow up one level, 140 ms | `whileHover` (CSS-accelerated on rows) | n/a (no hover) |
| `enterUp` | 8 px rise + fade, 340 ms expo-out, 35 ms stagger (cap 8) | `Reveal`, `PageTransition`, `.stagger-in` | `enterUp(i)` in list rendering |
| `popover` | 4 px rise + 0.98 scale, 220 ms | menus, dropdowns, tooltips, selects | action sheets |
| `page` | 6 px rise, 520 ms emphasised | route transitions with scroll reset | `Stack` screen options + `sheetEnter` |
| `sheetEnter/Exit` | 24 px + spring `sheet` | modal/dialog body entrance | bottom sheets, drawers |
| `shimmer` | 1.6 s sweep, 120 ms delay | `animate-shimmer` on skeletons | `shimmer` worklet on skeleton families |

### 5.3 The reduced-motion contract

- Web: every animated component calls `useReducedMotion()` and drops transforms (fades may remain); the
  pre-paint theme script and boot splash check `prefers-reduced-motion` before animating.
- Native: `ReduceMotion.System` is read through `AccessibilityInfo`; entrances collapse to opacity-only.
- Duration tokens stay constant, so timing logic (timeouts, toasts) is unaffected by the preference.

Never animate more than one property family at rest (transform **or** opacity), never exceed 520 ms for a
state change, and never block the first paint on an animation.

## 6. Components

### 6.1 Web (`apps/web/src/components`)

**Primitives (14)** — `button`, `card`, `badge`, `status-badge`, `input` (incl. `Field`, `InputWithIcon`,
`SegmentedControl`), `skeleton`, `empty-state` (+ 5 presets), `stat-card` (`StatGrid`, `AnimatedNumber`,
`Sparkline`), `data-table` (`Column`, `Pagination`, `usePager`), `dialog` (+ `AlertDialog`, `ConfirmDialog`),
`menu` (Radix dropdown + tooltip), `progress` (`Progress`, `ProgressRing`, `CapacityMeter`, `toneForRatio`),
`avatar`, `toast` (+ `Toaster`). One barrel: `import { Button, Card } from '../components/ui'`.

**Patterns (3)** — `page-header` (`PageHeader`, `SectionHeader`), `page-transition` (`PageTransition`, `Reveal`),
`command-palette` (`CommandPaletteProvider`, `⌘K`, recents in `mentis.recentRoutes`).

**Layout (2)** — `app-shell` (rail + glass header + drawer + offline banner), `nav-list` (`BrandMark`, grouped nav).

### 6.2 Native (`apps/mobile/components/ui`)

`text` (10 variants + tone + tabular), `surface` (`Card`, `Screen`, `AuroraBackdrop`, `Divider`, `Row`),
`button` (+ `IconButton`), `badge`/`StatusPill`, `skeleton` family, `progress` (`ProgressBar`, `ProgressRing`,
`CapacityMeter`), `empty-state` (+ presets), `swipe-row`, `segmented`, `avatar`, `feedback` (banner +
`AnimatedCheck`), `list-row`.

Screens: `app/(tabs)/{today,tasks,inbox,more}`, `app/login`, `app/register/[id]`, with `_layout` providers
(theme → auth → lock gate) and a glass tab bar with haptic press feedback.

### 6.3 Component rules

- Variants come from the kit (`intent`, `tone`, `size`), never from bespoke class strings in pages.
- Interactive elements are ≥ 44 px (web) / 48 dp (native) hit targets.
- Every list has four states defined up-front: loading (skeleton), empty (with a next action), error (with retry),
  and full.
- Touch/click feedback is mandatory: `whileTap`/`usePressScale` plus the matching haptic on native.
- Focus is visible on every surface (`ring-4` brand-soft on web; explicit focus styles on native inputs).

## 8. Adoption recipe (adding a screen)

1. Wrap the route content in the shell (web: `P(perm, <Page/>)`; native: a file under `app/`).
2. Start with `PageHeader` (web) or `Screen` (native — its `title` / `subtitle` / `right` slots are the header):
   title, one-line purpose, actions.
3. Compose from the kit — `Card`, `StatGrid`, `DataTable`/`ListRow`, `Field`, `EmptyState` presets.
4. Render all four list states; never ship a blank panel.
5. Add motion through the presets, not bespoke `transition` values.
6. Verify: `npm run build && npm test` (web), `npm run typecheck` (native), root `npx vitest run` if tokens or
   domain logic moved.
